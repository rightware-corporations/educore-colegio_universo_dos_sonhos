# 5. Arquitetura técnica canónica

## Stack

`docs/colus/architecture/platform-stack-v1.md`

- React + TypeScript + Vite;

- OpenAPI;
- HikariCP;
- PostgreSQL dedicado por escola;
- Redis dedicado por escola;
- S3-compatible Object Storage;
- Flyway migration job separado;
- Transactional Outbox;
- OpenTelemetry.

## Backend

`docs/colus/architecture/backend-architecture-v1.md`

Estilo:
> **MODULAR MONOLITH + HEXAGONAL BOUNDARIES**

Fluxo:

```text
api
→ application
→ domain
← infrastructure
```

Módulos previstos:
- identity;
- people;
- academic;
- admissions;
- finance;
- communication;
- governance;
- integration.

## Database

`docs/colus/architecture/database-architecture-v1.md`

Decisões:
- PostgreSQL operacional dedicado por escola;
- schemas por domínio;
- core transacional normalizado;
- UUID para entidades de domínio;
- FKs/constraints reais;
- query-driven indexes;
- ACID;
- optimistic locking;
- transactional outbox;
- audit append-only;
- idempotency;
- Redis nunca source of truth;
- migration role separada do runtime;
- encrypted backups + PITR;
- sharding apenas muito mais tarde, se realmente necessário.

## Security

`docs/colus/architecture/security-architecture-v1.md`

Princípio:
> **DEFENSE IN DEPTH**

Browser production:
> **OIDC/OAuth2 Authorization Code + PKCE + BFF/session pattern**

Regras:
- refresh token não fica em localStorage;
- HttpOnly/Secure/SameSite cookies;
- RBAC + contextual ABAC;
- privileged roles com MFA;
- CSRF protection;
- CORS allowlist;
- HSTS/CSP/security headers;
- Redis-backed rate limiting;
- private DB/Redis;
- TLS/in-transit + at-rest encryption;
- separate DB roles;
- upload quarantine + malware scan;
- secrets fora do Git;
- audit append-only;
- structured logs com redaction;
- dependency/secret/SAST/container scans;
- SBOM;
- environment separation;
- backup restore tests.
